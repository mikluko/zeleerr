# zeleerr

A one-page front for the family in front of [Seerr](https://github.com/seerr-team/seerr),
Radarr and Sonarr: search for a movie or a series, request it, and watch the download
queue. It has no sign-in of its own and trusts a header set by the authenticating proxy
in front of it.

## How it works

- The signed-in user's email comes from a request header, `X-Auth-Request-Email` by
  default, as oauth2-proxy sets it with `--set-xauthrequest`. A request without it gets
  401.
- Each email is matched to a Seerr user. If Seerr has none, zeleerr creates a local one
  and gives it the permissions in `ZELEERR_PERMISSIONS`; a user Seerr already has keeps
  its own.
- A request goes to Seerr on behalf of that user. A series is requested with every
  season.
- The queue is read from Radarr and Sonarr directly. A series' episodes are folded into
  one entry per season. Below the downloads come the requests Seerr is still processing
  with nothing downloading yet.
- The page speaks English or Russian, whichever the browser's `Accept-Language` prefers,
  and names movies and series in that language where TMDB has the name. Each links to its
  page in Seerr.

## Run it

```shell
SEERR_URL=http://seerr:5055 SEERR_API_KEY=... \
RADARR_URL=http://radarr:7878 RADARR_API_KEY=... \
SONARR_URL=http://sonarr:8989 SONARR_API_KEY=... \
go run ./cmd/zeleerr
```

The image is `ghcr.io/mikluko/zeleerr`.

## Configuration

| Variable | Default | Meaning |
|---|---|---|
| `SEERR_URL`, `SEERR_API_KEY` | | Seerr, without `/api/v1` |
| `SEERR_PUBLIC_URL` | `SEERR_URL` | Seerr as the browser reaches it, for links |
| `RADARR_URL`, `RADARR_API_KEY` | | Radarr |
| `SONARR_URL`, `SONARR_API_KEY` | | Sonarr |
| `ZELEERR_ADDR` | `:8080` | listen address |
| `ZELEERR_USER_HEADER` | `X-Auth-Request-Email` | header carrying the user's email |
| `ZELEERR_PERMISSIONS` | `160` | Seerr permission bits for a user zeleerr creates: REQUEST and AUTO_APPROVE |

`/healthz` answers without the header.

## seerr-gate

The image also carries `/seerr-gate`, a reverse proxy that serves Seerr's own pages to
people the authenticating proxy has signed in, without a sign-in of Seerr's. It keeps a
Seerr session for each email and puts it on their requests; the browser never holds one.
It signs in as the local Seerr user of that email with the password
HMAC-SHA256(`GATE_KEY`, email), and sets that password through the API, creating the
user if Seerr has none, when the sign-in fails. Seerr wants the current password to
change the API key owner's own, so a new `GATE_KEY` needs that user's password reset by
hand.

| Variable | Default | Meaning |
|---|---|---|
| `SEERR_URL`, `SEERR_API_KEY` | | Seerr, without `/api/v1`, and a key with `MANAGE_USERS` |
| `GATE_KEY` | | key the passwords derive from |
| `GATE_ADDR` | `:8081` | listen address |
| `GATE_USER_HEADER` | `X-Forwarded-Email` | header carrying the user's email |
| `GATE_PERMISSIONS` | `160` | Seerr permission bits for a user the gate creates |

`/_gate/healthz` answers without the header.

## Development

The API clients in `internal/{seerr,radarr,sonarr}` are generated by
[oapi-codegen](https://github.com/oapi-codegen/oapi-codegen) from the specs in `api/`:

```shell
go generate ./...
go test ./...
```
